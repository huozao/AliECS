# GitHub to ECS auto deploy flow

## Goal

Daily releases should follow one simple path:

1. Codex or a human pushes code to a GitHub branch.
2. A PR is created and merged into `main`.
3. GitHub Actions builds images and pushes them to GHCR.
4. GitHub Actions connects to ECS through SSH.
5. ECS syncs `/root/AliECS` to the latest `origin/main`.
6. ECS backs up and restores private env files.
7. ECS runs the latest `deploy/ecs/deploy.sh`.
8. ECS runs `deploy/ecs/post-deploy-smoke.sh`.
9. If deployment or smoke checks fail, GitHub Actions runs `deploy/ecs/collect-diagnostics.sh` and prints a redacted diagnostic summary in the workflow logs.

In the normal flow, no one needs to SSH into ECS just to run `git pull`.

## ECS private config

These files are private runtime config and must not be committed:

- `/root/AliECS/deploy/ecs/release-meta.env`
- `/root/AliECS/deploy/ecs/runtime.env`

`release-meta.env` is maintained manually on ECS. It stores the database password, login secret, GHCR pull credentials, WeCom credentials, and other real values.

`runtime.env` is generated by `deploy.sh` from `release-meta.env`. Do not treat it as the long-term source of truth.

## How GitHub Actions protects env files

During the SSH deploy step, GitHub Actions:

1. Backs up `release-meta.env` and `runtime.env` into `/root/AliECS-private-backup/github-actions`.
2. Runs `git fetch origin main --tags`.
3. Checks out `main`.
4. Restores any env files that old checkouts still tracked, so local secret edits do not block `git pull --ff-only`.
5. Runs `git pull --ff-only origin main`.
6. Copies the backed-up ECS private env files back into `/root/AliECS/deploy/ecs/`.
7. Runs the latest `deploy.sh`.

This keeps `compose.prod.yml`, `deploy.sh`, migrations, and new service definitions in sync with GitHub `main`, while real secrets remain only on ECS.

## Post-deploy smoke checks

`post-deploy-smoke.sh` verifies:

- `public-web`, `admin-ui`, `backend-api`, `postgres`, and `doc-sync-worker` exist in production compose.
- Backend health check is reachable.
- `http://127.0.0.1:8080` and `http://127.0.0.1:8081` are reachable.
- Postgres has `external_sources`, `external_fields`, `external_records`, `sync_runs`, and `sync_requests`.
- Current doc-sync source, run, and record counts are printed for quick inspection.

The smoke script does not call WeCom by default. To opt in on ECS, set:

```bash
POST_DEPLOY_RUN_DOC_SYNC=true
POST_DEPLOY_DOC_SYNC_PROFILES=COMPANY_B
```

Only enable this for stable profiles. External WeCom permissions, trusted IP rules, or data-field changes should not block ordinary releases unless you explicitly choose that behavior.

## Failure diagnostics

When the deployment job fails after SSH is available, GitHub Actions runs `collect-diagnostics.sh` automatically. The script prints:

- Git status and latest commit on ECS.
- Whether important env variables are present, using `SET` or `MISSING` plus value length.
- Parsed `DATABASE_URL` scheme, host, database, and password length without printing the password.
- Production compose services and container status.
- Backend, public-web, and admin-ui local HTTP checks.
- Doc-sync table counts and recent sync run summaries.
- Recent backend, doc-sync-worker, and postgres logs with common secret patterns redacted.

This should make most failures diagnosable from the GitHub Actions log. You should not paste full `release-meta.env`, `runtime.env`, database URLs, tokens, app secrets, or SSH keys into chats or issues.

## Recovery

If `git pull --ff-only` fails, ECS has local changes outside the protected env files. Inspect first:

```bash
cd /root/AliECS
git status -sb
```

Do not run `git reset --hard` unless you have confirmed those local changes can be discarded.

## Manual verification commands

```bash
cd /root/AliECS

grep -n "doc-sync-worker" deploy/ecs/compose.prod.yml
ls db/migrations/0005_doc_sync.sql

docker compose --env-file /root/AliECS/deploy/ecs/runtime.env \
  -f /root/AliECS/deploy/ecs/compose.prod.yml \
  ps
```

Run full WeCom sync manually:

```bash
docker compose --env-file /root/AliECS/deploy/ecs/runtime.env \
  -f /root/AliECS/deploy/ecs/compose.prod.yml \
  run --rm doc-sync-worker python -m app.main sync-wecom-full
```
