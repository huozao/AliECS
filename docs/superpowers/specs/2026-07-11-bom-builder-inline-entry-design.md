# BOM Builder 行内录入重构设计（2026-07-11）

## 背景与问题

`/bom-builder/`（PR #176/#178 上线）用于录入新开发配方并写入畅捷通 T+。现状是「顶部统一搜索 → 结果列表点添加 → 回到子件表格填数量」的三段跳，录一行原料要在页面上来回移动，手机上尤其难用。用户核心诉求：**每一行直接搜索，选中后直接填数量**，不要统一搜索区。

顺带发现的必修 bug：该页面登录仍是旧密码弹窗，打的 `/v1/auth/login` 已被 break-glass 关闭（403），**登录实际是坏的**，本次一并改为 SSO。

## 需求画像（已与用户确认）

- **手机为主**：触屏优先，数字键盘、大点击区；桌面自然可用即可。
- **典型 5–15 行子件**；行上**只填数量**，预出仓库/子 BOM 版本基本不填（收进行内「更多」）。
- **父件基本都是新建存货**（不是搜已有）：录入项为编码、名称、版本号、生产数量、默认 BOM；类别默认「物料清单」、单位默认「kg」。
- **新原料偶尔出现**（约 1–2/10 次）：搜不到时给兑底入口即可，弹窗表单可接受。
- 交互模式选定 **方案 A：常驻搜索行**（备选的全屏搜索弹层、顶部搜索自动化两案已否）。

## 页面结构（三块，一列到底）

1. **父件卡** — 默认即新建表单
2. **子件列表** — 已选行 + 底部常驻搜索行
3. **吸底提交条** — 状态摘要 + 单一主按钮

原「保存草稿」「服务端校验」独立按钮取消：草稿自动保存；校验合并进提交动作。

## 父件卡

```
┌ 父件 ──────────────────────┐
│ 编码 [____]  名称 [______] │
│ 版本 [V1] 生产数量 [1] kg  │
│ ☑ 设为默认 BOM             │
│ 类别: 物料清单 ▾ 单位: kg ▾│
│ ▸ 高级（成品率/预入仓库/    │
│    工艺路线/车间/规格）      │
│ 或：选用 T+ 已有存货（链接）│
└────────────────────────────┘
```

- 类别/单位选项来自 `GET /v1/tplus/inventory-create-options`；**按名称匹配预选**「物料清单」「kg」，不写死编码。实现前须核对 T+ 现有 BOM 父件与原材料库存货的真实类别/单位取值（现代码父件默认类别 `06`、单位 `1`，与「物料清单/kg」的对应关系待验证；若名称匹配不到则不预选，下拉仍可手选）。
- 成品率默认 1、规格可空，连同预入仓库/工艺路线/车间收进「高级」折叠。
- 「选用 T+ 已有存货」为次要路径：点开出现与子件相同的行内搜索（scope=all），选中后父件区变为只读展示（编码/名称/单位），可撤销回新建态。

## 子件常驻搜索行（核心交互）

- 列表底部常驻一个空搜索行，placeholder「搜原料：编码 / 名称 / 规格」。
- 输入 ≥1 字符，**250ms 防抖**调 `GET /v1/tplus/inventories?q=…&scope=material&limit=20`，下拉展示：`名称 · 规格 · 单位 · 可用量`。
- **点选结果**：该行立即转为「已选行」（名称/规格/单位/可用量只读 + 数量输入框），**焦点自动落到数量框**（`inputmode="decimal"`），下方自动长出新的空搜索行。
- 数量填完直接操作下一行（或键盘「下一项」跳转），无确认按钮。
- **搜不到兑底**：结果列表末尾固定「＋ 新建 "关键词"」→ 打开现有自定义存货弹窗，名称预填关键词、类别预选原材料对应类、单位预选 kg；确认后直接落为已选行（source=custom，带「新建 T+」标签）。
- **重复选择**：滚动定位到已有行并高亮闪烁，不重复添加。
- 每行右侧「⋯」菜单：删除、预出仓库、子 BOM 版本。
- 父件不能同时是子件、子件不能与父件同码：沿用现有前端检查与提示。

## 吸底提交条

- 内容：`N 项 · 合计 <按单位分组的数量和> · 草稿已自动保存`＋主按钮「校验并写入 T+」。
- **合计按单位分组**：如 `8 项 · 合计 42.5 kg`；出现非 kg 单位时并列显示（`42.5 kg ＋ 3 个`），**不同单位不加成一个数**。
- 主按钮流程：本地检查（父件已定、≥1 子件、数量>0）→ 自动保存草稿 → `POST …/validate` → 通过则 confirm 弹窗（含「其中 N 个自定义存货会先创建到 T+」提示）→ `POST …/submit`（幂等键沿用 `bom-builder-<draftId>`）→ 轮询 `GET /v1/tplus/bom-submissions/<id>` 展示 等待/写入中/成功/失败/需人工复核。

## 数据流与自动暂存

- **后端接口零改动**：inventories / inventory-create-options / bom-drafts CRUD / validate / submit / submissions 全部沿用。
- 自动保存两层：
  1. 每次状态变更同步写 **localStorage**（断网、杀进程不丢）；
  2. **防抖 2s** 同步服务端草稿（无 draftId 则 POST，有则 PATCH），提交条显示保存状态。
- 进页面时若 localStorage 有未提交内容：提示「继续上次未完成的配方？」（继续/丢弃）。
- 提交成功后清 localStorage 与本地状态，展示成功态并提供「再录一个」。

## 登录与错误处理

- 登录改为 SSO 直跳：`location.href = API_BASE + '/v1/auth/oidc/login?rd=' + encodeURIComponent(location.pathname+location.search)`；删除密码弹窗与 `/v1/auth/login` 调用；按钮文案「登录（SSO）」，与全站一致（见 PR #173 模式）。
- 未登录：页面结构可见，聚焦搜索/点提交时提示「请先登录（SSO）」。
- 搜索接口失败：搜索行行内红字 + 重试，不弹全局错误；401 清 token 引导重新登录。
- 提交失败/需人工复核：沿用现有状态框文案与「不自动重试、转人工」原则。

## 非目标

- 不改后端任何接口与校验/提交语义。
- 不做批量粘贴、从已有 BOM 复制（配方规模 5–15 行暂不需要）。
- 不为桌面单独设计键盘快捷流（自然可用即可）。

## 验证清单

1. 单测：无后端改动则无新增；若默认值核对导致 `inventory-create-options` 调整，补对应测试。
2. 真机（手机）走通闭环：新建父件（默认类别/单位正确）→ 常驻行连加 3 个原料（含一次搜不到→新建自定义）→ 数量合计正确 → 提交到 T+ → 轮询到 success。
3. 中断恢复：录一半杀掉页面重进，提示恢复且内容完整。
4. 登录：未登录点登录（SSO）→ Authelia → 回跳 `/bom-builder/`。
