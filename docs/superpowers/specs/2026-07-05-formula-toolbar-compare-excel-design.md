# 配方查询页工具栏重组 + 对比表 Excel 新版式（方案B）设计

日期：2026-07-05
状态：已与用户确认（生成路线、方案B、视图自定义项均已拍板）

## 背景与目标

`/formula/` 配方查询页两处体验问题：

1. 对比工具栏一排平铺 7 个按钮 + 6 个筛选 pill，功能无分类，越加越乱。
2. 「下载对比表Excel」产物是 HTML 伪 `.xls`，Excel 打开后 div/span 被拍平，
   比例、箭头、数量挤成一团，横条不渲染，数字全是文本，肉眼对比困难。

已拍板的决策：

- 对比表 Excel **继续走前端 HTML 伪 `.xls` 路线**（不动后端、秒下载），只重排版面。
- 版式采用**方案 B（紧凑式）**：每版本一列，格内三行。样例已真机确认。
- **不做冻结窗格**（Office HTML 冻结声明在用户的 Excel 中不生效，已验证，放弃）。
- 打开时「格式与扩展名不符」警告是该路线固有代价，接受。

## 一、工具栏重组（前端 `services/public-web/formula/index.html`）

新布局四组，下拉菜单**鼠标悬浮展开**（同时支持点击开合，兼容触屏）：

```
[生成对比]  [快速选择 ▾]  [下载 ▾]  [视图 ▾]   筛选pill：全部 仅差异 仅替换 仅新增/删除 仅比例变化 仅一致
```

- 筛选 pill 属高频操作，保持外露不折叠。
- 「生成对比」保留为主按钮。

### 快速选择 ▾（操作 state.selectedKeys 后 renderAllCompare）

| 菜单项 | 行为 |
|---|---|
| 全选 | 现有逻辑保留 |
| 全不选 | 新增：清空 selectedKeys（表格显示「请选择配方查看详情」空态） |
| 反选 | 新增：selectedKeys 取补集 |
| 只选默认BOM | 新增：仅保留 `defaultBOM==='1'` 的版本 |
| 只选启用+默认BOM | 现有逻辑保留（非停用 或 默认BOM） |

选择变化后沿用现有 baseKey/targetKeys 兜底逻辑（基准被取消勾选时自动移到首个已选版本）。

### 下载 ▾

| 菜单项 | 行为 |
|---|---|
| 原始明细（全部工作表） | 现有 `downloadRawResult()` 不变 |
| 只下载「配方表_人眼版」 | 新增：请求 `GET /v1/recipes/download/{file_id}?sheet=human` |
| 对比表 Excel | 新版式生成（见第二部分） |

- 查询未返回 file_id 时，前两项置灰（disabled），与现有 downloadRawBtn 隐藏逻辑等价。
- 下载菜单在未生成对比数据时「对比表 Excel」同样置灰。

### 视图 ▾（自定义对比明细显示项，checkbox 多选）

控制网页对比表格 + 对比表 Excel 导出（所见即所得）。默认全勾选，
存 localStorage（key `formula_display_options`），跨会话记忆。

| 选项 | 控制内容 |
|---|---|
| 显示规格列 | 规格型号列（取代现有「隐藏规格列」按钮，旧按钮删除） |
| 显示数量 | 单元格数量行 |
| 显示百分比 | 单元格比例行 |
| 显示±基准箭头 | ↑/↓ 及差值标注 |
| 显示「新增」标记 | 新增角标 |
| 显示占比条 | 单元格底部横条（仅网页；Excel 中对应比例格底色深浅） |

- 「显示数量」「显示百分比」不允许同时取消（至少留一个主数值）：取消最后一个时自动把另一个勾回并提示。
- 渲染入口：`renderCompareCell` / `renderCompareTable` 按选项条件输出对应片段。

## 二、对比表 Excel 新版式（方案B，前端生成）

替换 `downloadCompareResult()` 的表格拼装逻辑，产物仍为 `application/vnd.ms-excel` 的 HTML 伪 `.xls`。已确认的样例即验收基准（`方案B_紧凑式_对比表.xls`），要点：

### 结构（每版本一列）

1. 标题行「配方比例对比表」。
2. 元信息行：基准 / 目标列表 / 导出日期 / 当前筛选。
3. 差异统计行：替换 n · 新增 n · 删除 n · 变化 n · 一致 n。
4. 表头一行：状态 | 子件编码 | 子件名称 | 规格型号 | 单位 | 各版本列
   （版本列头两行文字：父件编码 + 版本号；基准列标「★ 基准」）。
5. 数据行**按状态分组排序**：替换→新增→删除→比例变化→一致→历史，组内按子件编码。
6. 尾部说明行（图例）。

### 单元格（版本列，格内最多三行，`<br>` + `mso-data-placement:same-cell` 保持同格）

- 第 1 行：**比例**（加粗）。
- 第 2 行：数量 + 单位（灰、小号）。
- 第 3 行：±基准变化（红↑升 / 绿↓降，同网页配色）或紫色「新增」。
- 该配方不含此物料 → 「—」灰底，明确区分于 0。
- 底色深浅 = 该配方内部占比高低（近白→暖棕线性插值，替代横条）；基准列固定米色底 `#f6efe2`。

### 样式

- 状态列彩色：替换蓝 / 新增紫 / 删除红 / 变化橙 / 一致灰 / 历史棕。
- 表头深棕底白字；列宽通过 th width 指定。
- 不写冻结窗格 XML（已验证无效）。

### 导出遵循当前状态

- 跟随当前筛选 pill（现状已如此）。
- 跟随「视图」显示项：取消数量则不输出数量行，取消箭头则不输出第 3 行的箭头，
  取消规格列则不输出规格列（占比条选项映射为比例格底色，Excel 侧不受该开关控制，始终保留底色）。

## 三、后端：人眼版单表下载（`services/backend-api`）

- `GET /v1/recipes/download/{file_id}` 新增可选 query 参数 `sheet=human`。
- `sheet=human` 时只生成/返回含 `配方表_人眼版` 单工作表的 xlsx；
  缓存文件与全量导出分开（如 `{file_id}_human.xlsx` 路径变体），沿用延迟生成 + 上下文过期语义。
- 文件名：在 `recipe_raw_export_filename` 基础上插入「人眼版」标识。
- 实现方式：`save_recipe_workbook` 加 `human_only` 开关（或拆出单表写出函数），
  复用现有 `_write_human_review_sheet`。
- 参数非法值（非 `human`）返回 400。

## 四、不做的事

- 不改 BOM 范围下拉、查询表单、成本核算区（导出核算Excel 等按钮维持原位）。
- 不引入任何 JS 依赖库。
- 不做冻结窗格、不消除伪 .xls 打开警告。
- 不改后端对比数据结构（对比矩阵仍由前端 buildCompareMatrix 计算）。

## 五、测试与验证

- `tests/test_formula_frontend.py` 现有断言随按钮 id/结构更新；
  新增断言：下拉菜单元素、视图选项默认全选、localStorage key、
  下载菜单含 `sheet=human` 请求路径。
- 后端新增测试：`sheet=human` 返回的 xlsx 仅含 `配方表_人眼版`；非法 sheet 值 400。
- 真机验证：查询多版本配方 → 三个下拉悬浮/点击展开 → 快速选择五项行为 →
  视图取消勾选逐项生效且导出一致 → 人眼版单表下载 → 对比表 Excel 与已确认样例版式一致。
