# 企微智能表格结构备份设计

## 背景

当前 AliECS 已每天同步企微 A、企微 B 的智能表格，并将文档、工作表、字段和记录快照保存到 Postgres。历史排查发现，分享链接中的 `s3_*` 不能替代企微 OpenAPI 使用的真实 `dc*` docid；如果创建文档时未保存 docid，后续恢复困难。

本功能在企微 A 中创建一份独立的“企微智能表格结构备份”，持续保存两个企微环境的文档定位信息和有效结构，并让 `/health/` 数据导出的“创建副本”结果自动进入备份。

## 目标

- 在企微 A 创建一份专用智能表格备份文档。
- 企微 A、企微 B 各使用一张“最新结构”工作表。
- 每行对应一个智能表格文档，而不是单个 sheet。
- 保存文档 docid、文档名、每个 sheet 的 sheet_id、sheet 名和字段结构。
- 每日全量同步完成后更新全部已登记企微文档。
- `/health/` 创建副本后，可靠地将新文档推送到备份。
- 仅在结构发生变化时保存一个新的结构版本，支持后续查验和对比。

## 非目标

- 不备份业务记录内容、附件、图片或人员数据。
- 不保存企微接口响应中的权限、请求、审计等冗余元数据。
- 不尝试将 `s3_*` 分享链接转换为丢失的 `dc*` docid。
- 不修改现有业务智能表格的结构或记录。

## 方案选择

采用“Postgres 字段快照驱动 + 企微备份任务队列”。现有 doc-sync worker 已将企微结构同步到 `external_sources` 和 `external_fields`，备份流程复用该结果，避免每日重复调用企微读取接口。

未采用以下方案：

- 再次直接扫描所有企微文档：重复请求多，且仍依赖同一登记来源。
- 新建完整审计数据库再投影到企微：能提供更复杂的分析，但超出当前结构备份需求。

## 企微备份文档

文档名：`企微智能表格结构备份`

工作表：

1. `企微A-最新结构`
2. `企微B-最新结构`
3. `结构变更历史`

备份文档由企微 A 自建应用创建，使用现有 `WECOM_COMPANY_A_*` 凭据和 `WECOM_DOC_ADMIN_USERS`。创建接口返回的真实 docid 保存到生产环境变量 `WECOM_STRUCTURE_BACKUP_DOCID`。备份文档不登记为普通同步源，避免递归备份自身。

## 最新结构行模型

唯一键为 `env_profile + ":" + docid`。每个智能表格文档在所属公司工作表中只有一行。

公共字段：

- `唯一键`
- `企业配置`
- `智能表格名称`
- `docid`
- `来源链接`
- `来源类型`
- `状态`
- `工作表数量`
- `字段总数`
- `结构哈希`
- `企微修改时间`
- `源同步时间`
- `备份更新时间`
- `结构最后变化时间`
- `创建来源`
- `创建副本请求时间`

工作表结构按固定列组保存，最多支持 20 个 sheet。每个列组包含：

- `工作表NN名称`
- `工作表NN编码`
- `工作表NN类型`
- `工作表NN可见性`
- `工作表NN字段结构`
- `工作表NN字段数量`

`NN` 从 `01` 到 `20`。当前线上文档最多 10 个 sheet，预留到 20 个。超过 20 个时禁止静默截断：任务失败、记录错误并等待重试，直到扩展备份表结构。

## 字段结构格式

每个 sheet 的字段结构使用稳定排序的紧凑 JSON 数组。单个字段只保存：

```json
{
  "id": "field-id",
  "name": "字段名",
  "type": "FIELD_TYPE_TEXT",
  "order": 1,
  "config": {}
}
```

`config` 仅保存影响表格含义或行为的配置：

- 单选、多选选项及顺序；
- 公式表达式；
- 关联、引用和查找目标；
- 日期、数字、百分比、货币格式；
- 自动编号规则；
- 主字段标记。

不保存重复的标题/类型字段、同步状态、权限信息、请求元数据或整段 `raw_json`。字段按企微返回顺序排列；缺少显式顺序时按字段 ID 稳定排序。

线上现状中，文档级最小结构最大约 15797 字符，但拆分到单个 sheet 后最大约 3215 字符，因此按 sheet 列组存储能够避免超长单元格，同时保持人工可读性。

## 结构哈希和版本历史

结构哈希基于规范化文档快照计算 SHA-256。哈希输入包括：

- 文档名；
- sheet 名、sheet_id、类型、可见性和顺序；
- 字段 ID、名称、类型、顺序及有效配置。

同步时间、来源链接和运行状态不参与结构哈希。

`结构变更历史` 每行保存一个文档结构版本：

- 当前结构行的全部公共字段和 20 个 sheet 列组；
- `版本唯一键`，格式为 `env_profile + ":" + docid + ":" + 结构哈希`；
- `前一结构哈希`；
- `变化摘要`；
- `触发来源`：`daily`、`copy-auto` 或 `manual`；
- `检测时间`。

历史行只保存当前版本完整结构，并通过 `前一结构哈希` 指向前一版本，避免同时重复保存旧、新两份大结构。

## 数据流

### 每日同步

1. worker 按现有流程完成企微 A、企微 B 全量同步。
2. worker 从 Postgres 读取所有 active 的企微 doc/sheet/field 快照。
3. 每个文档生成一个规范化结构快照和结构哈希。
4. 为每个文档创建幂等备份任务，事件键为 `daily:<日期>:<profile>:<docid>`。
5. worker 消费任务并更新对应公司工作表。
6. 新文档或哈希变化时追加结构历史；哈希未变化时只更新时间和状态。

### 创建副本

1. `/v1/exports/external-doc/{source_id}/copy` 创建企微副本并取得真实 `new_docid`。
2. backend 在同一数据库事务中登记 doc 级 source、创建现有 `copy-auto` 同步请求，并创建结构备份任务。
3. worker 先同步新副本文档，获得全部 sheet 和字段。
4. worker 消费备份任务，在对应公司最新结构页签新增一行。
5. 历史页签追加 `copy-auto` 首次结构版本。

## 持久化任务队列

新增表 `wecom_structure_backup_jobs`：

- `id`
- `source_id`
- `event_key`，唯一
- `trigger`
- `status`：`pending`、`running`、`success`
- `attempt_count`
- `next_attempt_at`
- `last_error`
- `created_at`
- `started_at`
- `finished_at`

重复事件通过 `event_key` 幂等。失败任务回到 pending，并按有限退避设置 `next_attempt_at`；主企微同步不因备份失败而失败。成功任务保留审计记录。

## 写入规则

- 目标工作表按 `唯一键` 查询现有行。
- 不存在时新增最新结构行，并追加首次结构历史。
- 存在且哈希变化时更新最新行，并追加新结构版本。
- 存在且哈希相同时更新时间和状态，不追加历史。
- `copy-auto` 新文档必须产生首次历史版本。
- 历史表按 `版本唯一键` 去重；重试和重复消费不得产生重复最新行或重复历史版本。

## 错误处理

- 备份文档未配置：任务保留并输出明确配置错误。
- 目标 sheet 或字段缺失：初始化命令可幂等补齐，任务随后重试。
- 企微网络/API 失败：记录脱敏错误并按任务队列重试。
- 源文档尚未完成首次同步：任务延后，不写入空结构。
- 文档超过 20 个 sheet：明确失败，不截断结构。
- 单个 sheet 字段结构超过企微文本单元格限制：明确失败并报告文档、sheet 和字符数。

## 配置和运维入口

新增环境变量：

- `WECOM_STRUCTURE_BACKUP_DOCID`
- `WECOM_STRUCTURE_BACKUP_PROFILE`，默认 `COMPANY_A`
- `WECOM_STRUCTURE_BACKUP_MAX_SHEETS`，默认 `20`
- `WECOM_STRUCTURE_BACKUP_ENABLED`，默认 `false`

新增 worker CLI：

- `init-wecom-structure-backup`：创建或幂等校验备份文档、工作表和字段。
- `sync-wecom-structure-backup`：为全部企微文档入队并消费一次，供部署验证和人工补偿。

正式启用时，先创建备份文档并保存 docid，再设置 `WECOM_STRUCTURE_BACKUP_ENABLED=true`。

## 测试和验收

自动测试：

- 规范化结构稳定排序和 SHA-256 哈希；
- raw field 到精简字段结构的转换；
- 20 个 sheet 列组生成和超限失败；
- 新文档新增、同哈希更新、变更追加历史；
- 每日任务和 copy-auto 任务幂等；
- 失败重试和源结构未就绪延后；
- 创建副本 route 同时创建同步请求和备份任务；
- worker 每日全量同步后入队并消费备份任务。

线上验收：

- 企微 A 中存在三张设计约定的工作表；
- 企微 A、B 最新结构行数分别等于 active 文档数；
- 抽查多 sheet、多字段文档的 docid、sheet_id、名称和字段类型；
- 首次同步为每个文档生成一个历史版本；
- 重跑不增加重复历史；
- 人工触发一次已有 copy-auto source 的补偿任务，确认最新结构和历史记录均正确；
- worker 日志、任务队列和原有企微同步保持健康。

## 兼容性和发布边界

- 默认关闭，未配置时不改变现有同步行为。
- 不新增生产依赖，沿用 requests、psycopg 和现有企微 API 客户端。
- 不在代码或数据库迁移中保存凭据。
- 创建企微文档、修改 ECS runtime env 和正式部署属于本功能的显式发布步骤。
