# 首页移动端重设计（public-web index.html）

日期：2026-07-12
范围：仅 `services/public-web/index.html` 单文件（纯前端静态页）

## 背景与问题

首页 hydwang.xyz 是配方/库存/系统功能的统一导航页，运行时从后端
`GET /v1/features?include_all=true` 拉取功能列表渲染。当前在手机上体验差：

1. **文字重复**：卡片标题与说明高度雷同（「原材料库存」/「原材料库存查询」、
   「排产登记表」/「排产信息登记」、「产品命名登记」/「产品命名录入」）。
2. **技术噪音**：每张卡都印「分类：业务查询」「权限：inventory.raw.read」，
   对终端用户无意义，且各占一行。
3. **卡片过胖**：`min-height:190px`，手机单列排开，16 个功能滚动过长。
4. **分类未被利用**：后端已按 业务查询/业务录入/质检/个人/系统/工具 分类，
   但页面只把「工具」单独成组，其余全堆在一个大网格。
5. **顶栏拥挤**：右上角按钮横向溢出，「API Health」被截断显示为「th」。

## 目标

- 手机端信息密度高、少滚动、像原生 App。
- 去掉重复文字与技术字段噪音。
- 电脑端同一份 HTML/数据，仅靠 CSS 断点自适应，不维护两套。
- 不改后端，不改 `/v1/features` 返回结构。

## 设计

### 1. 顶栏瘦身
- 标题「首页」缩小；删除副标题「配方、库存、系统状态与权限功能的统一导航页」。
- 右上角只保留主按钮 **登录（SSO）/ 退出登录**。
- 「API Health」「Admin UI」「刷新数据」收进一个「⋯」下拉菜单
  （管理/调试用途，不占用户首屏）。

### 2. 功能区：分组 + 紧凑列表
- 用后端已有的 `category` 做分组小标题，固定顺序：
  **业务查询 → 业务录入 → 质检 → 工具 → 个人 → 系统**。
  （未在此列表中的分类追加在末尾，按原 sort_order。）
- 每个功能一行，整行可点：`emoji  名称            ›`。
- 删除「分类：」「权限：xxx」字段。
- **说明文字规则**：仅当说明确实补充了标题之外的信息时才以小灰字显示在名称下一行；
  与标题雷同的复读型说明不显示。判定方式：前端维护一份「显示说明的 feature code
  白名单」（如 `formula_query`、`formula_color_space`、`ash_calculator`、
  `ai_file_transfer`），或等价地维护「隐藏说明」黑名单。白名单更保守，采用白名单。
- **emoji**：前端维护 `code -> emoji` 映射（16 项），扫视更快。
  未映射到的功能给一个分类级默认 emoji 兜底。

### 3. 锁定 / 未开放项
- 无权限或 `status==='reserved'` / 无 `url` 的功能：**置灰 + 🔒**，仍列在所属分组。
- 点击弹提示：未登录/无权限 → 引导点右上角登录；reserved → 「未开放」。
- 登录后重新拉取，自动亮起。

### 4. 响应式布局
- 结构与数据单一来源，仅 CSS 换列数：
  - **窄屏（手机）**：每分组内功能单列，一行一个。
  - **宽屏（电脑）**：每分组内功能 `grid` 多列自适应
    （`grid-template-columns: repeat(auto-fill, minmax(~260px, 1fr))`，
    屏越宽列越多，约 2–3 列）。
- 整页 `max-width:1120px` 居中（沿用现值），宽屏不拉满。
- 带说明小灰字的行在多列中会略高，**接受这种参差**（说明照常显示，信息优先）。

### 5. 视觉
- 沿用现有暖色主题（`--bg:#f7f5f0`、`--card:#fffdf8`、`--primary:#6f5e46` 等）。
- 分组卡内为细列表行，行间细分隔线；每行触摸高度 ≥48px。
- 去除胖卡的 `min-height:190px`。

## 数据与接口

- 继续调用 `GET /v1/features?include_all=true`，字段沿用：
  `code / title / description / url / category / required_permission /
  status / sort_order / allowed`。
- 新增的展示逻辑（emoji 映射、说明白名单、分组顺序）全部在前端 JS 常量中，
  不依赖后端改动。

## 非目标（YAGNI）

- 不改后端 `DEFAULT_FEATURES` 或数据库。
- 不新增分类、不改权限模型。
- 不引入前端框架/构建步骤，保持单文件静态页。
- 不做搜索框、收藏、拖拽排序等增强（本次不需要）。

## 验证

- 本地起静态页（现有 stub/预览方式），在窄视口与宽视口分别检查：
  - 手机：单列、分组、无技术字段、锁定项置灰。
  - 电脑：分组内多列自适应，整页居中不拉满。
- 登录态切换：未登录锁定项置灰，登录后亮起并出现受限功能。
- 冒烟：现有 Playwright 静态页冒烟流程（若适用）。
