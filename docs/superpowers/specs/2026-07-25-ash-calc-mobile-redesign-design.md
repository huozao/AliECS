# 灰分计算器移动端重构设计

- 日期：2026-07-25
- 目标文件：`services/public-web/tools/ash-calc/index.html`（单文件，自包含 HTML/CSS/JS）
- 线上路径：`https://hydwang.xyz/tools/ash-calc/`

## 1. 背景与问题

现有页面是**桌面电子表格范式**：样品作列、指标作行，两栏并排（录入宽表 + 结果宽表）。
CSS 从 `v5` 补丁到 `v14`（现文件约 26–244 行）全在跟表格横向滚动、列宽压缩、点击弹浮层看全文较劲——这是**横向宽表在窄屏天然别扭**的信号，不是没调好。

手机端具体痛点：

- 录入：样品平行输入是宽表，每样品挤进 112px 窄列，输 4 位小数的坩埚重量又滑又点，易错。
- 结果：`#process`、`#compare` 两张表都要左右拖动，还得点单元格弹浮层看全文（`enhanceTooltips`）。
- 顶部 6 个按钮挤成一排，手机上换行、点击目标小。

## 2. 已确认的场景约束

1. **主场景**：实验台边用手机录入数据 → 重构重点在输入端，要求录入快、防错、单手可用。
2. **录入节奏**：按阶段横扫全部样品（先全部 W₀，再全部 W₁，再全部 W低，再全部 W高），对应批量过炉流程。
3. **样品数**：常见 2–4 个（一个基准 + 若干目标）。工具本身仍允许更多，但手机布局按 2–4 优化。

## 3. 方案选择

**采用「响应式分层」**：以约 760px 为断点。

- 桌面（≥760px）：**完全保留**现有渲染与交互，一行不改。
- 手机（<760px）：换成「阶段步进录入 + 纵向结果卡」。

数据模型与全部计算函数（`fillers`、`samples`、`calc`、`calcOne`、`ordered`、`report`、`buildReport`、`exportCSV`、`printReport` 等）**完全复用**，移动端只新增独立的渲染层与 CSS。

被否决的方案：
- **移动优先统一重构**（全平台步进+卡片）：要重写桌面渲染，桌面老用户熟悉的宽表对比丢失，超出需求。
- **表格转置 + 粘性首列**：仍是表格范式补丁，录入依旧在窄列滑动，未解决根本问题。

## 4. 移动端交互设计（<760px）

### 4.1 整体骨架

- 顶部：精简标题 + **阶段圆点进度条**（可点跳转，支持乱序跳）。
- 圆点下方两个大 Tab：`录入` / `结果`。
- 底部：固定操作条（主操作突出，见 4.4）。

### 4.2 录入 = 阶段步进器

步骤序列（按过炉节奏）：

| 步 | 名称 | 内容 |
|---|---|---|
| ① | 测试条件 | 低温/低温时间/高温/高温时间，4 个大输入框，一屏 |
| ② | 样品设置 | 每样品一张竖卡：名称、角色（基准/目标N）、材料类型、主要填料、自动模式；增删=大按钮 |
| ③ | 称 W₀ | 纵向列出全部样品，每个一个大号数字框 |
| ④ | 称 W₁ | 同上 |
| ⑤ | 称 W低 | 同上 |
| ⑥ | 称 W高 | 同上 → 完成后自动切到「结果」Tab |

称重屏（③–⑥）单个样品行结构：

```
┌────────────────────────────┐
│ 旧481 (基准)                │   ← 样品名 + 角色徽标
│ ┌────────────────────────┐ │
│ │  78.49              g  │ │   ← 高≥48px, inputmode="decimal",
│ └────────────────────────┘ │      点击全选, 唤起数字键盘
│ 净重 9.99g · 低温残留 61.5% │   ← 实时小字, 边录边看合理性
└────────────────────────────┘
```

- 实时小字：随该阶段可算的中间量刷新（W₀ 阶段可不显示；W₁ 后显示净重 m₀；W低 后显示低温残留率；W高 后显示高温灰分）。
- 阶段圆点上标该阶段完成度（如 `3/3`）。
- 底部固定「上一步 / 下一步」大按钮；末步按钮为「查看结果」。
- 保留现有优点：示例值灰字占位（`input.ex`）、聚焦全选（`focusin` + `select()`）。

### 4.3 结果 = 纵向卡片

不再用横向宽表。每个样品一张结果卡，纵向排列：

- 卡头：样品名 + 角色（基准/目标N）+ 材料类型。
- 卡体：有机组分 / 功能粉体（炭黑·钛白粉·色粉，按模式取标签）/ 填料折算 / 粉体合计 / 低温残留率 / 高温灰分 / 闭合率。
- 目标卡的每个指标直接标「较基准 +x.x%」，红升蓝降（复用现有 `plus`/`minus` 语义）。
- 高亮语义（最大粗体 / 最小斜体）在卡片内保留或简化为「较基准方向色」——以卡片可读性为准，不强求还原表格的三值高亮。
- 校验与风险提示：沿用现有纵向 `.warn` 卡片列表，无需改动结构。

### 4.4 底部固定操作条（手机）

- 主操作突出：`导出PDF`、`复制报告`。
- 次要操作（增加样品、恢复示例、导出CSV、重新计算）收进「更多」弹层，或放到对应步骤内（如「增加样品」放步骤②内）。
- PDF 报告走 `@media print`（现文件约 246–279 行），逻辑不变，手机照常可导出。

## 5. 实现边界与复用

### 5.1 复用（不改）

- 状态与数据：`fillers`、`samples`、`baseFillers`、`demo`、`userEdited`。
- 计算：`calcOne`、`calc`、`ordered`、`cls`、`globalCond` 等。
- 输出：`report`、`buildReport`、`printReport`、`exportCSV`。
- 桌面渲染：`renderSamples`、`renderFillers`、`processTable`、`compareTable`、`renderWarn`、`enhanceTooltips`。

### 5.2 新增（移动层）

- CSS：一个 `@media (max-width:760px)` 段，隐藏桌面宽表容器、显示移动骨架；步进器、称重卡、结果卡样式。移动样式**只在断点内生效**，不污染桌面。
- JS：新增移动端渲染函数（建议命名前缀 `m*`，如 `mRenderStepper`、`mRenderStageInputs`、`mRenderResultCards`、`mGoStep`），内部读写同一份 `samples`/`fillers`，改动后调用现有 `calc()`。
- 视图切换：依据 `matchMedia('(max-width:760px)')` 决定初始化移动骨架还是桌面骨架；两套 DOM 共存于同一页面，用 CSS 显隐，避免 resize 时重建状态丢失。

### 5.3 数据一致性要求

- 移动端与桌面端**共享同一份 `samples` 数组**，任一端修改后统一走 `calc()` 重算，保证切换设备/旋屏时数据不丢、结果一致。
- 移动端字段的读写 key 必须与现有模型一致（`w0/w1/wlow/whigh/name/role/type/filler/mode/constant/blackResidue`），不新增并行字段。

## 6. 非目标（YAGNI）

- 不改计算公式、填料库默认值、模型逻辑与警示文案。
- 不改 PDF 报告版式与 CSV 结构。
- 不改后端 `DEFAULT_FEATURES` / 迁移 / 路由 / 权限（页面仍是公开静态页）。
- 不做本地持久化（localStorage 草稿）——本轮不引入，若后续需要另开需求。
- 不做多语言、不引第三方库（保持自包含单文件）。

## 7. 验证方式

- 桌面回归：≥760px 下逐项确认现有录入表、结果表、填料库、复制、CSV、PDF、示例占位、聚焦全选行为与改动前一致。
- 移动新功能：<760px（浏览器 DevTools 移动模拟 + 真机）走完整流程——① 测试条件 → ② 样品设置（增/删/改角色触发唯一基准约束 `ensureBase`）→ ③–⑥ 四阶段录入 → 结果卡显示 → 导出PDF/复制/CSV。
- 数字键盘：iOS/Android 上称重框唤起小数键盘（`inputmode="decimal"`）。
- 旋屏/断点切换：跨 760px 来回切换，数据不丢、结果一致。
- JS 语法与作用域：与现文件同为内联脚本，检查无语法/作用域错误，核心入口 smoke（录入触发 `calc()` 刷新结果）。

## 8. 部署（沿用现有手法）

- public-web 是纯 nginx 静态镜像（根路径实为 `/usr/share/nginx/html/`，非早期记录的 `/html`）；热更新 = `docker cp` 静态页进 `ecs-public-web-1` 供验证；验证 OK 后走正式部署。
- AliECS 走分支 + PR，不直推 main（自动守卫会拦）。合并触发 release-deploy 出 `VYYYYMMDDNNN` 标签。
- 纯前端静态页变更，无后端/迁移影响。

## 9. 实施变更记录（2026-07-25 上线，经 7 轮真机实测迭代）

以下为相对第 4–6 节初版设计的增补，均随本次 PR 落地：

1. **阶段步进器文字化**：阶段圆点由数字改为短标签（条件/样品/W₀/W₁/W低/W高）+ 完成度 `n/总`；每步标题下增加一句操作指引（tip）。
2. **称重输入两列并排**：称重屏样品输入改为 `.m-wgrid` 两列网格（原为纵向单列），2–4 样品更省纵向空间、输入框宽度更贴合数字录入。
3. **已填数据速览（转置综合表）**：由「样品行×称重列」改为「指标行×样品列」，同一指标横向对比各样品；并入物料净重变化链 `m₀ 原样净重 → m低 低温残留净重 → m高 灰分净重` 与低温残留率、高温灰分率。
4. **信噪分层**：含坩埚毛重（W₀/W₁/W低/W高）为核对用「噪音」，灰化弱化为背景；净重/率为信号并凸显；当前阶段块（毛重+净重+率）整块蓝色高亮 + 左侧竖条。
5. **报告历史缓存（localStorage）—— 修订第 6 节非目标**：原 §6 列「不做本地持久化」，本轮按用户需求改为**已做**。出报告（导出 PDF / 复制报告）自动存快照，用户可在「历史记录」面板（桌面工具栏 / 手机「更多」）查看、载入、删除，或手动「保存当前为记录」。仅存于用户本机浏览器 localStorage，不跨设备、不上后端；跨设备长期留存需后端存库，属另开需求。

术语约定（速览表）：毛重 = 坩埚+残留（人工称量原值）；净重 = 扣坩埚后的物料质量；m高（高温残留净重）即灰分净重。
