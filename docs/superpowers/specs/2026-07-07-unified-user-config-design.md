# 统一用户配置编辑面 设计

日期：2026-07-07
状态：设计已与用户拍板，待写实施计划

## 背景与目标

系统里"常见用户配置"目前散落在三种形态：

1. **doc_sync 配置**（已上线 PR#160）：飞书「配置表」键值行 → 校验 → 写 DB `integration_sync_config` → worker 热读 DB。单向 表→DB。
2. **bridge 规则配置**（已上线 PR#149/#161/#164）：飞书「规则配置表」`global-default` 行 → bridge 运行时**直读飞书**（TTL 缓存，不落 DB）→ env 兜底。
3. **硬编码**：T+ 导出模块说明、库存仓库范围等，写死在代码里，**没有编辑面**。

两个已上线的形态是**两套技术骨架**——不是谁做错，是服务边界决定的：backend/worker 共享 DB 走「表→DB→热读」，bridge 隔离（**不连 postgres**）只能走「表→直读+缓存」。

**用户诉求：编辑面统一。** 核心原则一句话：

> **每一项常见用户配置都只有一个明确的"编辑家"——不能"零家"（硬编码）、也不能"两家"（多处可改）。**

编辑面统一 ≠ 把所有东西塞进飞书。已经有好编辑家的（如首页功能入口有 admin 后台）就留在原地，只在总览页挂链接。

## 范围

### 纳入本设计
- 新建独立「系统配置」多维表格作为飞书侧编辑面。
- 统一配置**表形态**为"每域一张表、配置项 = 带类型的列"。
- 尽量用类型化字段（复选框/单选/多选/数字）约束输入，避免人工输入无效内容。
- 迁移当前硬编码配置：T+ 导出模块说明、库存仓库范围（多选选项从 T+ 仓库档案自动同步）。
- 新增配置：ChatGPT 对话模式默认（单选 极速/均衡/高级）。
- 只读「生效面」管理页：汇总所有域的生效值 + 来源 + 最后拉取时间 + 应急覆盖 + 编辑家链接。
- 顺带修复：webdock2 英文界面对话模式选择器错配。

### 明确排除
- 密钥、基础设施地址、性能/超时、认证参数 → 永不进表格，维持 SOPS+age。
- 首页功能入口（14 项）→ 已有 DB 表 `features` + admin 后台 CRUD（`/v1/admin/features`），**不迁飞书**，只在生效面挂入口链接。

## 架构决策

### D1. 独立「系统配置」多维表格
新建一个专用多维表格（新 app_token），里面**只放配置**，不与会话管理台的运行数据（消息/任务/会话）混。内部按域分表：

| 表（sheet） | 归属服务 | 生效路径 |
|---|---|---|
| 同步配置 | doc-sync-worker + backend | 表→DB→worker 热读 |
| bridge 规则 | openclaw-bridge | 表→直读+TTL |
| 对话模式 | openclaw-bridge | 表→直读+TTL |
| T+导出说明 | backend | 表→DB→backend 热读 |
| 库存仓库范围 | backend | 表→DB→backend 热读 |

代价（实施要覆盖）：doc-sync 需把新簿登记为数据源；bridge 需新增指向新簿 app_token / table_id 的 env（并入 SOPS）。

### D2. 统一表形态 = 类型化列，不是键值行
配置表**不再**用 `配置键 | 配置值(文本)` 的键值行模式——单一文本列没法对不同配置用不同字段类型。统一约定为：

> **每个配置项 = 一张域表里的一个带类型的列；域的当前生效配置 = 该表里一行（如 `global-default` / 单例行）。**

这正是 bridge 规则表已有的形态。**doc_sync 现有键值表要拉齐成此形态**（改的是飞书表的编辑形态 + 解析层；DB `integration_sync_config` 生效面 schema 可不动）。

### D3. 字段类型映射（"选项化"落点）

| 配置项 | 字段类型 | 选项来源 |
|---|---|---|
| 各开关（同步开关/暂停/处理中卡片/调试尾注） | 复选框(7) | — |
| 文档同步周期 | 单选(3)：1/6/12/24/48/168 小时 | 静态预设 |
| 文档同步起点时间 | 文本(1) HH:MM + 校验（时间连续不宜枚举） | — |
| 对话模式默认 | 单选(3)：极速/均衡/高级 | 静态预设 |
| T+导出模块说明（8 条） | 文本(1) | 天然自由文本 |
| 库存原料仓库 / 成品排除仓库 | 多选(4) | **动态：从 T+ 仓库档案同步选项** |

原则：值域有界 → 用复选框/单选/多选把无效输入挡在录入处；只有自由文本（说明文案）用文本列。**校验层保留**，作为 API/手滑/选项漂移的兜底（非法值不落库 + 可见报错）。

### D4. 通用配置框架（含地基补强）
- **配置项注册表**：每个配置项声明 `(域, 列名, 字段类型, 选项/取值范围, 解析函数, DB 落点/直读)`。参考现有 `sync_schedule.py:CONFIG_REGISTRY`，推广为通用结构。
- **拉取器**：单向 表→（DB 或直读缓存）；校验合法才生效，非法值跳过并记可见错误；无变化则 noop。
- **地基补强（P1 前置）**：
  1. `create_feishu_bitable_field` 目前只发 `{field_name, type}`，**无 `property`**。需扩展支持写 `property.options`，才能建单选/多选并带选项。
  2. 建列/建表助手当前写死 `feishu_session_console_app_token()`。需把 **app_token 参数化**，以支持新独立簿。
  3. 单选/多选的选项**幂等对齐**：静态枚举建列时写入固定选项；动态枚举（仓库）由同步任务把 T+ 档案编码灌进选项集（新增不删已用，或按档案对齐——实施计划细化）。

### D5. 对话模式默认 + webdock2 英文修复
两层，互相独立：

- **配置层（bridge）**：`feishu_chat_mode` 当前未设置返回 `""`。新增"对话模式默认"配置（单选 极速/均衡/高级 → 规范值 fast/balanced/advanced），当会话无粘性模式时用默认值兜底而非 `""`。
- **执行层（webdock，顺带修）**：`webdock/src/browser/selectors.py:85-87` 胶囊选择器写死中文 `has-text('极速'/'均衡'/'高级')`，英文界面命中不了；`chatgpt_page.py:41-43` 别名表缺 webdock2 实际英文标签（`balanced` 缺 `Medium`、`advanced` 缺 `High`）。
  - 修：别名表补 `balanced += "Medium"`、`advanced += "High"`；选择器改为语言无关——抓所有 `menuitemradio`，文本过别名表映射，不再靠中文 `has-text`。
  - 归属：webdock 仓，与飞书表框架是两回事，一并交付。

### D6. 生效面管理页
后端聚合各域生效值的只读端点 + 前端总览页：
- 每项显示：生效值、来源（飞书某表/DB 默认/env 兜底）、最后拉取时间。
- 每项指向其编辑家（飞书对应表 / admin 后台链接）。
- **应急覆盖**：管理页可临时覆盖某项（不改飞书表），并可暂停表格拉取（复用 doc_sync 已有 `pull_paused` 思路，推广到各域）。

## 分期

- **P1 框架 + 拉齐**：补地基（建列带选项 + app_token 参数化）；通用配置注册表/拉取器；建独立「系统配置」簿；doc_sync 迁类型化列形态；bridge 规则表/对话模式并入新簿。
- **P2 迁配置**：T+ 导出说明、库存仓库范围（含仓库选项自动同步）、对话模式默认；webdock2 英文界面修复。
- **P3 生效面**：只读汇总管理页 + 应急覆盖 + 编辑家链接。

## 数据流（统一后）

```
飞书「系统配置」簿（编辑面，字段类型约束输入）
   │  单向拉取 + 校验（非法值跳过+报错）
   ├─ 走 DB 的域（同步/导出说明/仓库范围）→ integration 配置表 → backend/worker 热读
   └─ 直读的域（bridge 规则/对话模式）→ bridge TTL 缓存
                                              │
                              生效面管理页（只读汇总 + 来源 + 应急覆盖）
```

## 错误处理与兜底
- 拉取/读取任何失败：降级到 DB→env→代码默认，**绝不阻断主流程**（沿用现有 best-effort 约定）。
- 校验：非法值不落库/不生效，错误可在日志与生效面可见。
- 字段类型漂移（如文本列被误建成复选框）：沿用 `reconcile_type` 删列重建（仅对可再生的 bridge 托管列）。

## 测试策略
- 注册表解析/校验：单测覆盖合法/非法/边界/未知键/状态列跳过。
- 选项对齐：单测覆盖静态枚举建列、动态仓库选项同步（新增/漂移）。
- 对话模式默认兜底 + webdock 语言无关匹配：webdock 侧针对中英文 DOM 各一组断言。
- 生效面聚合端点：来源标注与应急覆盖优先级。
- 遵循各服务既有测试入口（backend pytest、doc-sync worker `PYTHONPATH=src`、webdock pytest）。
