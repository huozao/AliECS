# V6 市场观察台三页拆分设计

## 目标

将当前首屏同时加载实时行情、历史曲线、事件、持仓和原始证据的单页，拆为三个按用途隔离的数据入口，降低首屏响应体、DOM 数量和持续刷新成本。数据库中的观察、事件和账户证据保持不变；只改变查询和展示边界。

## 页面与数据边界

### 实时显示

路径 `/market/realtime/`，旧 `/market/` 继续指向此页。首次请求只读取最近 15 分钟的 8 个 AU 合约观察，返回成交曲线、模型价格带、当前挂单位置和对冲合约排序。禁止在此请求事件详情、历史持仓、标注和原始逐笔全文。浏览器维护固定 15 分钟环形窗口，刷新只追加增量。

### 当日错单跟踪

路径 `/market/today/`。首次请求只返回 UTC+08 交易日的事件索引（事件编号、发生时间、合约、方向、阶段、状态），并分页。用户选中事件后，才请求有界的阶段曲线、挂单、成交、对冲及平仓数据。

### 历史错单复盘

路径 `/market/history/`。首次请求只返回排除当日后的事件索引，支持日期、合约和状态筛选及游标分页。选中事件后按事件编号读取详情和有界曲线；不预取其它事件详情。

## 后端约束

新增或明确区分轻量索引与详情接口；所有接口设置最大时间窗口、最大行数和分页上限。实时接口服务端强制 15 分钟上限，不能通过客户端参数恢复为全日数据。详情接口返回数据缺口和证据状态，不以空数组冒充未验证。

## 前端约束

三页共享认证、时间格式化、图表和错误提示组件；实时页不渲染原始 JSON 或大段 ID 文本。页面切换销毁旧页定时器和图表监听器。缺失 XAUUSD 源时显示缺失边界与源年龄，不插值。

## 验收

1. 实时页首屏网络请求不包含事件详情和历史持仓，8 个合约各有一组 bounded 曲线数据。
2. 当日页首屏只请求事件索引；选中一笔后新增且仅新增一笔详情请求。
3. 历史页首屏只请求分页索引；未选择事件时详情请求数为 0。
4. 浏览器验证三页切换、登录权限、空数据/缺口状态、桌面与窄屏布局；测量响应字节数、行数和首次渲染时间。
5. 既有快照、事件、持仓和标注 API 契约测试继续通过。
